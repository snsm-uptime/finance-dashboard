## What went well

### 1. The second code review caught a shipped-to-browser regression

Story 3.5.1's review **round 1** deleted `ui/postcss.config.js`, believing it was stray config from an undocumented commit (`b3826d7`). It was not — `git show 3c26d4c` proved the story's own implementation commit authored it. Without it, Next.js/Turbopack never invokes `@tailwindcss/postcss`, and **Tailwind was never compiled at all**: `.next/static/chunks/*.css` shipped literal, unprocessed `@theme{...}` / `@custom-variant dark ...;` source text to the browser with zero generated utility classes.

Review **round 2** found it, restored `ui/postcss.config.mjs`, and verified the fix against real build output (`@layer theme/base/components/utilities` present, raw `@theme` text gone).

**Critically, the fix landed before 3.5.2 merged** — `c332d71` / PR #40 preceded PR #39. Had it not, Stories 3.5.2 and 3.5.3 would have been built and "visually verified" against a stylesheet Tailwind never touched.

### 2. Token discipline survived a full stack swap

Every story opened with a mandatory read of AD-12 / AD-23 and the Story 3.1 token table. The Warm Balance hexes were never re-picked; `@theme` points only at `var(--…)`, never at literal hexes. Single source of truth preserved end-to-end — the exact failure mode a styling migration usually produces.

### 3. Story 3.5.4 refused to manufacture work

The convention-lock story found all four ACs already satisfied by `sprint-change-proposal-2026-08-10.md` (pre-applied ahead of the code migration). Its own Dev Notes instructed: *"say so plainly, don't manufacture busywork edits to look productive."* Final File List: bookkeeping only. A verification story that correctly concluded "already correct" and documented the verification instead.

### 4. Epic 1 retro follow-through was 90%

9 of 10 Epic 1 action items are `done`; one remains `open` (session hashing/HMAC, token cleanup, 1.1 hygiene). This worked because the items were converted into **tracked stories** via Correct Course (Epic 1.5) rather than left as a list. The mechanism is proven — keep it.

## What didn't

### 1. A test that could not fail

Story 3.5.1's original bridge test `readFileSync`'d `globals.css` and substring-matched `@theme` in the **source**. That assertion holds whether or not Tailwind ever ran. It also asserted only 2 of 16 `@theme` entries and used `resolve("app/globals.css")`, dependent on `process.cwd()`.

**Root cause class: asserting on pipeline inputs instead of pipeline outputs.** Fixed in-story (the test now compiles through real PostCSS), but the lesson generalizes beyond CSS.

### 2. CI does not run `npm run build` — and still doesn't

`.github/workflows/ci.yml:52–72` runs the `ui` job as lint → typecheck → `test:coverage`. There is **no build step**, and `ci.yml` is the only workflow — **no Docker build in CI either**. Nothing in the automated pipeline would have caught the 3.5.1 regression, and that remains true today.

**Decision (Sebas, this retro):** not adding a build step to CI — the Docker build is the meaningful gate. **Recorded as an accepted risk, with the caveat that this gate is manual/local, not automated.** The compensating control is Action Item 2 below.

### 3. Story 3.5.3's verification gates were never executed

Task 6 is largely **unchecked** in the story record: visual regression, Light→Dark→System theme switching, and mobile viewport checks are all open boxes. The lint/typecheck/test/build sub-items are ticked with the note *"tooling not available in environment, but code is valid."* AC #3 was reported as "gates prepared" rather than passed.

The 20 review patches that followed included substantive defects the story's own gate would have caught: hard-coded hex violating AD-12, WCAG AA contrast failure on disabled state, `100vh` mobile reflow, sticky hover on touch devices, RTL breakage.

**Resolution (Sebas, this retro):** these 12 surfaces have since been **verified through real use** across Epic 4. No outstanding parity risk; no action item. The process gap — a dev agent self-certifying visual parity without a browser — is the lesson, not the current state.

### 4. Story 3.5.2 has no recorded review at all

3.5.2 migrated all nine Soft-Ledger primitives — the design-system template every later screen copies from — and its record contains **no Review Findings section**. Its Debug Log reads *"No blockers or unexpected findings during implementation. All conversions straightforward."* Its comparably-scoped sibling produced 20 findings.

3.5.4's own review independently flagged that 3.5.2 sat at `review` in `sprint-status.yaml` while its code was already merged to `main`. A silent record is indistinguishable from an unreviewed one.

### 5. Status drift across three signals

Story 3.5.3's file simultaneously carried header `Status: review`, Completion Status `in-progress`, and `sprint-status.yaml` `done`. Three signals, three answers, carried into the next epic. `epic-3-5` itself also remained `in-progress` with all four stories `done`.

## Key insights

1. **Assert on outputs, not inputs.** A test that reads source text cannot verify that a build pipeline ran. This is what made the 3.5.1 regression invisible.
2. **A review that "fixes" something must prove the fix against real artifacts.** Round 1's verification — checking that `@theme` text appeared in output CSS — was true *because* Tailwind hadn't run. The check confirmed the bug.
3. **Convention locks work when they precede the migration.** AD-23 was pre-applied by the sprint change proposal *before* code moved, which is why 3.5.4 found nothing to fix and why Epic 4 never reintroduced a CSS Module.
4. **Retro items survive only as tracked stories.** Epic 1's 90% follow-through came from Correct Course, not from the list itself.
5. **File-count proxies are not compliance.** "0 `.module.css` / 13 `.module.scss`" proves the ban held; it does not prove the 13 are custom-only.

## Demo gate resolution

Epic 3.5's definition states in two places in `epics.md`, and inline in `sprint-status.yaml`: *"Do not start Epic 4 until Epic 3.5 demo gate passes."* Epic 4 nonetheless proceeded to 4.1–4.9 `done` with 4.10 in review.

**Gate condition A — "CSS Modules removed from `ui/`":** met and verified (0 files).
**Gate condition B — "Soft-Ledger + lists/auth chrome visual parity":** never formally executed as a checklist.

**Sebas's determination (this retro): a deliberate call — the gate was satisfied in practice.** The migration was judged sound from real use of the application, and the move to Epic 4 was made knowingly. Nine subsequent stories of new UI on the stack corroborate it empirically. **Epic 3.5 is closed as `done`.**

Process note for future epics: the decision was correct, but it was never *written down* at the time. Gate closure should be recorded explicitly — accepted or passed — rather than inferred later.
