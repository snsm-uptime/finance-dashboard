## 2. What Went Well

**Alice (Product Owner):** The product spine held end to end. A user can create a shared expense, see who owes what, and settle from real computed shares — not stubs. AD-21 survived intact: settle-up remains computed shares only, with no payment ledger writes sneaking in under delivery pressure.

**Charlie (Senior Dev):** Story 3.4 is the standout. The 2.6 deferred-work entry warned that settle would double-count if it summed receipt *and* item allocations, and told 3.4 to pick one subject grain. 3.4 read that warning, chose receipt-level-only allocation, and caught a residual double-count on the payer path during implementation. A trap logged one epic earlier was defused before it ever shipped. That is the deferred-work ledger working exactly as designed.

**Dana (QA Engineer):** CI earned its keep in 3.5. The local unit suite couldn't see it — `DATABASE_URL` was unset so integration was skipped — but CI caught that `fx_rate` wasn't quantized, so the create response returned `"525.00"` while the receipt read-back returned `"525.0000"`. Fixed at materialization on all three return paths. A real correctness bug, caught by the gate that was supposed to catch it.

**Elena (Junior Dev):** 3.6 turned an accessibility mistake into a durable rule. `aria-label` on a `<p>` is name-prohibited under WAI-ARIA 1.2, so it became a `<div role="status">` — which also gave us `aria-live="polite"` for free. The `onResolve`/`resolveLabel` discriminated union means a nameless button is now unrepresentable in the type system rather than caught in review.

**Amelia (Developer):** The review→patch→done loop held across every story that ran it. ~28 findings closed with fixes in-story, not deferred into a backlog nobody reads.

## 3. Challenges & Friction

**Story text describing a codebase that doesn't exist.** Two of six stories hit this. 3.3 carried a claim that the balances BFF route had zero tests; the dev checked `git log -S` and found the tests had landed in 3.1 (`5cec5de`), and correctly declined to duplicate them. 3.6's story text assumed a `ui/components/index.ts` barrel, a `ui/pages/[listId]/` directory, JSON i18n files with a translate hook, and `--color-muted`/`--spacing-4` tokens — none of which exist here.

Both devs did the right thing: verified against live code and followed the source-of-truth order in `project-context.md`. That is why `project-context.md` was updated on 2026-08-14 with verified Soft-Ledger conventions. But the same drift recurred at scale in Epic 4, where 4.5/4.6/4.7 were drafted against guessed file, method, and port names before 4.4's real implementation merged — requiring the 2026-08-17 Sprint Change Proposal. The pattern is real and it is not local to Epic 3.

**Postgres integration tests skipped locally in three of six stories.** 3.3 (Docker unresponsive, 184 passed / 95 skipped), 3.4 (integration tests deferred pending DB setup), 3.5 (`DATABASE_URL` unset).

**Sebas (Project Lead):** CI is the contract, and it worked — it caught 3.5's quantize bug. Local skips are a speed tradeoff, not a defect.

Recorded as the team's accepted position: local integration skips are an explicit speed tradeoff against a CI gate that has demonstrated it catches what the local suite misses.

**Uneven review depth.** Story 3.4 has no Review Findings section at all, while 3.2 carried 12 patch items. 3.4 was also the story doing the trickiest domain math. It happened to be right — the double-count fix was self-caught — but the depth of scrutiny didn't track the depth of risk.

**3.2's review load as a signal.** Twelve findings in one story, spanning a native `<select>` that should have been the Soft-Ledger `Select`, `noValidate` bypassing required fields, `"10.00 CRC"` instead of the `₡` CRC voice, `"undefined"` currency rendering, and domain amount precision exceeding `Numeric(18,4)`. It was also the first story to wire the manual-expense path end to end — new surface area concentrates findings.

## 4. Known State Carried Forward

**FX is materialized behind a stub transport.** Story 3.5 shipped `MaterializeFxService` and the `BccrClient` port, but the adapter is `UnavailableBccrClient`, which raises `FxServiceUnavailableError` by design — failing loud with a 503 rather than silently defaulting to 1:1. That was the right call for a manual-entry path where USD is only reachable via API (no currency picker in the UI form).

Epic 4 imports card statement lines through the same commit path. The first real BAC credit statement containing a non-CRC line will 503 at commit until real BCCR transport lands. Documented here as a known state, not converted to a work item — Epic 4's Correct Course cadence is the right place for it to surface with real evidence.

Other Epic 3 residue lives where it belongs, in `deferred-work.md`: dual expenses-list entry points (`ListExpensesService` vs `GetListExpensesStubService`), and `list_ledger_entries` silently skipping rows with NULL hand fields.

## 6. Key Insights

1. **A written warning in `deferred-work.md` changed an outcome.** 3.4 is the proof case. The ledger is worth the discipline it costs.
2. **Verification against live code beats trusting story text.** Both stories that hit stale story text resolved it correctly by checking. The habit is stronger than the documents.
3. **Story text drifts from the codebase whenever stories are drafted ahead of the implementations they depend on.** Epic 3 absorbed it story-by-story; Epic 4 needed a Sprint Change Proposal. The cost scales with the lead time between drafting and building.
4. **Failing loud beats defaulting quietly.** `UnavailableBccrClient` raising a 503 makes the missing transport impossible to miss, where a 1:1 fallback would have written wrong money into the ledger and stayed invisible.
5. **CI is the contract.** The team's accepted position, validated by 3.5.
6. **Review depth should track risk, not story size.** 3.4 carried the epic's hardest math and its lightest review.
