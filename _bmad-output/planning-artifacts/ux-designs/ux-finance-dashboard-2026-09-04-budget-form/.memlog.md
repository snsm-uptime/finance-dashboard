- (decision) Primary submit action becomes a full-width 'Create budget' button, separated from input fields (removes trailing + inside the currency/cap/name pill).
- (decision) New/edit budget form moves from inline-on-page to a sheet (opened via a trigger on /budgets), not inline anymore.
- (decision) Field grouping/layout is open — user wants to see 2-3 sketched directions before committing (name/cap/currency/dates/lists regrouping).
- (change) Pivoted away from the sheet/overlay direction. New direction: the create form is a skeleton/ghost budget card, styled identically to real budget cards, placed as the first item in the masonry list (no sheet, no separate surface).
- (decision) Ghost card fields: name uses the same minimal underline-style input as list rename (extract shared MinimalInput component for both lists and budgets). Days-left slot becomes a calendar icon that opens the date-range picker; once a range is chosen it morphs into the real day-count display. Source lists become a single ChipPicker-style trigger (same mechanism as OriginChipPicker: one trigger chip + slide-down options panel) instead of a row of toggle chips. Cap sits in the top-right corner. Submit is a circular corner badge button (+ icon), same visual pattern as the avatar photo-remove/upload badges on Account (absolute, rounded-full, bg-surface, border-border, ~2rem, offset outside the card corner).
- (decision) Currency is a small tag fused into the cap control, top-right corner of the ghost card (e.g. 'CRC 500' as one control; tapping the currency part changes it).
- (decision) ChipPicker generalized into a reusable single-or-multi component (refactor OriginChipPicker on top of it). Multi mode: selected values render as their own individual accent chips inline (click directly toggles off, no panel needed to deselect); one trailing '+' trigger chip opens the slide-down panel listing only the not-yet-selected options to add. Single mode keeps OriginChipPicker's existing one-trigger-chip behavior.
- (change) Corrected ghost-card layout per user: cap does NOT sit top-left/top-right — it replaces the real card's existing end-of-progress-bar 'Cap' label (bottom-right, inline within the bar-labels row), not a floating corner element. Calendar icon (-> days-left once a range is picked) stays top-right, matching the real card's day-count slot exactly. The '+' submit badge floats on the top-left corner of the card (overlapping the border), near the name field.
- (change) Plus/submit badge moved from top-left to top-right corner of the ghost card (near the calendar/days slot, floating outside the border, not overlapping the inline calendar icon which sits inset within the card padding).
- (assumption) [ASSUMPTION] Selected-list chips keep wrapping inline (same as real cards today, height handled by the existing masonry re-measure) rather than truncating. The add-list slide-down panel (unselected options) gets a bounded max-height with internal scroll so a large list count doesn't blow out the card/page when the panel is open.
